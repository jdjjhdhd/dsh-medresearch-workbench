# 医学文献与证据工作台：客户安装与模型配置

插件版本：0.2.4，面向 Windows x64。工作台扩展要求 dsh-worktable 0.4.0 或更高。

本交付包面向客户本机使用。工作台不需要客户改环境变量，也不需要把 API Key 写进项目文件。

## 1. 环境要求

- DeepSeek Harness 桌面版 `>= 0.2.1-rc.2`（宿主需提供 `ctx.llm`、`ctx.agentDefaultModel`、`ctx.sessionProjections`、`ctx.credentials`）。
- **`dsh-worktable >= 0.4.0` 必须已安装并启用**：本项目是 dsh-worktable 的自定义窗口；本机验收版本为 0.4.0。缺少该依赖时，安装器会停止安装并说明处理方式。
- **Node.js 20+**：Node.js 用于运行插件安装器及本地桥接服务。使用 Zotero 代理、本地文件保存等桥接能力时，需要保留 Node.js 运行环境并启动后台桥接服务。后台启动成功后，可以关闭启动窗口。交付包不携带 Node 运行时。
- 可选：Zotero 7+ 本地 API（只读）。
- **BioMCP 0.9.3 已随包提供**：`tools/biomcp.exe` 来自官方 Windows x64 发布包，完整许可证和来源/哈希位于同目录；无需安装 Python、uv、Rust 或单独配置 MCP 服务。真实检索需要联网。
- **Windows 运行库**：官方 BioMCP 程序依赖兼容的 Microsoft Visual C++ x64 / UCRT。程序不能启动时，页面会显示原因并给出[微软官方安装说明](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist)。请按本机情况安装后重新检测；本项目不会自动安装运行库。
- 演示 PDF：`fixtures/sample-paper.pdf`（PLOS Medicine 开放获取，CC BY）。交付包已包含，用于验证阅读、选中、批注、页码与引用回跳。

## 2. 安装/升级宿主插件

### 插件市场安装

在插件市场安装 `jdjjhdhd/dsh-medresearch-workbench`，按提示重启 DSH，即可在「工作台」中打开医学工作台。前提仍是已安装并启用 dsh-worktable；不会自动修改其他插件。

如果此前通过完整 ZIP 的安装脚本安装过旧版，请先双击新包内的 **旧版转市场安装.cmd**，然后回市场安装并在完成后重启 DSH。准备工具使用系统 Node，先备份并核对旧插件及登记，再只解除旧 junction；不迁移、覆盖或删除原工作台资料。解除链接后应先完成市场安装再重启。已经使用市场版的客户无需此步骤。

准备工具也保留旧页面与桥接版本。若要取得新业务功能，请用完整新版客户包更新应用文件，并保留业务 `data/` 与附件；单独切换安装渠道不会更新旧工作区的页面。

新安装会自动把包内资源部署到当前 profile 的 `medresearch-workbench/`，包括 HTML、PDF.js、桥接及经官方哈希核验的 BioMCP，不需要另外下载运行资源。资料保存在部署目录的 `data/`，与 pnpm 的包目录分开。已有有效本地安装登记时保留原工作台和数据目录。

若受管升级涉及桥接代码变更且旧服务仍存活，会停止本次部署并提示处理；不会结束未知进程，也不会启动第二个服务写同一资料库。

### 为已有资料关联 PDF 与 Zotero 刷新

在仅有题录或摘要的资料阅读台，点击「为本资料选择 / 关联 PDF」并选择文件；上传后继续使用原资料 ID，保留其笔记、任务和批注。若资料在上传期间被删除，会提示并停止关联，不另建一条资料。

Zotero 的独立附件条目本身已有 PDF 时，可识别其自身附件。已知非 PDF 的附件不会按 PDF 处理。Zotero 后续新增附件仍需手动刷新或重新导入，本版没有后台自动监听。

### 完整 ZIP 安装

1. 将整个交付目录放在客户本机任意位置。
2. 双击 **安装或升级医学工作台.cmd**，或者在该目录打开 PowerShell 执行：

```powershell
node scripts\install-model-plugin.mjs
```

3. 如果客户把交付目录**换到新位置**，先保留原有data及附件，再从新目录运行同一安装入口：安装器会核对依赖、链接/实体副本身份、运行代码，并更新当前profile的安装位置登记。不要仅复制plugin子目录；不能把node_modules当作工作台资料目录。
4. 重启 DeepSeek Harness（运行中的宿主有时会热加载，但以重启为准）。
5. 自检（不会调用付费模型）：

```powershell
curl.exe http://127.0.0.1:<DSH当前端口>/api/medresearch/model/health
```

看到 `"ok": true` 即表示宿主模型插件已加载。端口以 DSH 实际启动端口为准，不要写死。若桌面 host 对本地 HTTP 加了鉴权而返回 401，不代表插件未加载；以工作台“模型设置”里不显示“宿主接口不可用”为准。

若需回滚（只撤销本插件的 dependency/bundle/junction，保留其他插件配置）：

```powershell
node scripts\install-model-plugin.mjs --rollback
node scripts\install-model-plugin.mjs --verify
```

`--verify` 会打印插件**实际加载位置**和 `dsh-worktable` 版本。

## 3. 打开工作台

1. 重启 DSH 后，左下角“工作台”项目列表和“控制室”卡片会自动出现“医学文献与证据工作台”。首次打开会创建项目、默认“窗口1”并绑定本目录的 `医学研究工作台.html`；不需要手动改布局或找 HTML。
2. 点击项目即可打开页面。无 Zotero 也默认可用：首页/资料库点“＋ 导入 PDF”，选择或拖入自己的 PDF，进入阅读台后批注、笔记、问答、关联任务并保存。
3. 本地文件服务会在首次打开时自动检测/启动（默认 `127.0.0.1:8765`）；成功后可关闭启动窗口。失败时顶栏显示“本地服务未启动”，点“启动 / 重试服务”并按提示处理。Zotero 未安装/未启动不影响 PDF、模型问答和保存。
4. 顶栏点击“模型”徽标，进入“模型设置”。

首次启动默认空库，不自动加载演示资料、病例或任务。升级保留所有已有记录。旧版的演示记录可在顶部“清除演示数据”按钮确认后移除；真实资料会保留。也可从“数据与备份”主动载入演示。

### BioMCP 指示灯

- 绿色“BioMCP 0.9.3”：本地程序可运行，联网检索是否成功以实际结果为准。
- 黄色“BioMCP 未就绪”：点击查看“文件未找到”或“程序启动失败”。请保留完整 tools 目录；启动失败可能与运行库、架构或系统访问限制有关。
- BioMCP 失败后使用备用公开来源时，结果会保留回退原因；不把备用结果标为真实 BioMCP。部分上游未返回时会显示覆盖不完整。
- 中文查询不会被自动改写；结果不足时可尝试英文医学术语。零条结果不单独证明 BioMCP 故障。

### 项目、服务与目录移动

项目初始化只更新明确属于本插件的布局与标签，保留客户的命名、隐藏状态、窗口内容和其他标签。目录移动会核对绑定会话的工作目录，必要时新建正确目录的会话并保留旧会话；无法核实时会提示，不静默覆盖客户绑定。

本地文件服务的身份和根目录必须与当前项目一致；默认端口被其他目录占用时不会复用或杀进程。隔离测试可在启动 DSH 前设置 MEDWB_PORT，窗口自动采用宿主返回的端口，无需改 HTML。

0.2.3会在首选端口被占用时自动使用系统分配的空闲端口，并将实际地址记在本项目 `runtime/bridge-service.json`；宿主重开后重新核对归属再复用，不扫描端口范围、不结束旧项目进程。`MEDWB_PORT`指定的端口被占用时也遵循这一策略。runtime属于本机运行记录，不随客户包分发，不应跨目录复制。

安装登记在当前DSH profile的 `.medresearch-workbench-installation.json`。宿主从真实profile上下文读取并核对HTML、桥接、插件身份和运行代码；登记缺失/过期会明确提示重新运行完整目录的安装入口。若已确认属于本插件的实体副本版本或代码较旧，安装器会先将整个旧副本保全到本次profile备份的plugin-copy，再安装新版；失败会恢复原副本、登记与本插件配置。未知目录、错包、含未知文件或profile范围外路径均拒绝处理，不直接删除目录。成功输出会显示备份路径。

PDF 上传会保存相对路径与文件身份侧车，请随 data/uploads 一起移动。旧绝对路径仅在来源记录和文件哈希一致时迁移；无证据的旧路径保持原值，在“数据与备份”显示重新定位提示。不同项目的浏览器缓存分开；旧版无项目归属缓存仍保留，可从旧版导出后恢复到正确项目。

## 4. 模型设置

### 4.1 使用 DSH 模型（默认）

- 工作台只从当前工作台项目的**明确绑定**读取会话模型选择，包括服务商、模型与推理设置。
- 在 DSH 切换会话模型后，工作台的下一次请求使用新选择，无需重启。
- 同一项目存在**多个匹配绑定**时，不会任取一个；会明确回退“使用 DSH 默认模型（工作台存在多个匹配绑定，无法唯一确定）”。绑定会话已关闭/找不到绑定时同样明确回退。
- 账号和密钥由 DSH 现有 provider adapter 管理；工作台不读取、不复制 DSH 凭据。

### 4.2 自定义 API

- 服务商：OpenAI、DeepSeek、或“自定义 OpenAI 兼容服务”。
- 填写 API Base URL（可填到 `/v1` 或完整 `/chat/completions`）与模型名称；模型名称不写死。
- API Key 为密码输入框；勾选“在本机记住密钥”后按 **服务商 + 规范化 Base URL** 隔离保存到 DSH 宿主凭据库。
- **空密钥输入只在同一“服务商 + 地址”下保留已保存密钥**；更换平台或 Base URL 后不会静默沿用旧密钥，必须为新地址填写。删除密钥使用独立按钮“删除已保存密钥”。
- 保存后立即生效，无需重启客户端。
- 服务商/地址相同的模型名变更可以保留该地址的密钥；模型名不参与密钥隔离。

当前只支持 **OpenAI 兼容 Chat Completions**；Anthropic、Gemini 原生协议未实现，界面有明确提示。

## 5. 状态与失败

设置页会区分：

- 已选择但未测试；
- 测试成功（显示测试时间）；
- 未配置；
- 认证失败；
- 余额或额度不足；
- 请求被限流；
- 模型不存在；
- 网络失败；
- 超时；
- 宿主接口不可用。

只有真实取得非空模型回答才显示“测试成功”；HTTP 200、密钥存在或模型列表可读都不算生成通过。修改地址、模型、服务商或密钥会清除旧的测试成功状态。定时状态检查只读取设置，不调用付费模型；设置页打开时不会因后台轮询刷新表单。

**截断**：DSH 的 `finish=max-tokens` 或自定义 API 的 `finish_reason=length/max_tokens` 会明确显示“回答被截断”，不会当成完整回答；`content_filter` 会显示内容被安全过滤。**超时**会显示“请求超时”，不会标成成功。

## 6. 数据与隐私

- 文献、专题、笔记、批注、病例、任务数据在项目的 `data/workbench-data.json`；模型配置不在其中。
- API Key 不写入工作台 localStorage、`workbench-data.json`、日志、备份导出或源码。
- 自定义配置和 DSH 全局配置相互独立；工作台不会自动把同一份资料发送给另一个服务商。
- Zotero 保持只读；不运行数据库直写或清库脚本。
- 模型回答基于当前选中片段和页码/引文；无法从片段确认时会明确说明，不编造引用。

## 7. 限制

- 使用同一模型不等于继承 DSH 原生聊天历史；工作台每次显式构造本次问答所需的片段上下文。
- 自定义 API 的真实可用性取决于客户自己的服务商、额度和网络；工作台只负责准确发起和反馈。
- 交付包不含任何开发者账号、密钥、业务数据或本机绝对路径依赖。
