# 医学文献与证据工作台（客户交付版）

当前插件版本：0.2.4（Windows x64）。支持市场一键安装和完整客户包安装。项目初始化仅维护本插件创建的布局和标签，不接管客户同名项目或改写客户自行添加的窗口。

检索资料 → 加入专题 → 阅读原文 → 记录笔记 → 关联任务。支持真实 Zotero 只读导入、BioMCP 检索、PDF 阅读/批注，以及工作台内真实模型问答。

## 前提

- DeepSeek Harness `>= 0.2.1-rc.2`；
- **`dsh-worktable >= 0.4.0` 必须安装并启用**（本项目是它的自定义窗口）；
- **Node.js 20+**：Node.js 用于运行插件安装器及本地桥接服务。使用 Zotero 代理、本地文件保存等桥接能力时，需要保留 Node.js 运行环境并启动后台桥接服务。后台启动成功后，可以关闭启动窗口。
- Zotero 7+ 本地 API 为可选；**BioMCP 0.9.3 Windows x64 程序已随包提供**，无需另装 Python、uv 或 Rust。请保留整个 `tools/` 目录；真实检索需要联网。
- BioMCP 需要兼容的 Windows 运行库；程序启动失败时在“连接与来源”查看检测原因及[微软官方 Visual C++ x64 运行库说明](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist)。不会自动安装运行库或更改系统设置。

## 市场一键安装

已安装并启用 dsh-worktable 后，在插件市场安装 `jdjjhdhd/dsh-medresearch-workbench`，按提示重启 DSH，然后在「工作台」打开「医学文献与证据工作台」。不需要另外下载 ZIP 或运行安装脚本。

旧手动安装版切换到市场版前，请先双击本包的 **旧版转市场安装.cmd**，成功后再回到市场安装，完成后再重启 DSH。该工具先备份并校验旧插件，再只解除旧链接；不修改原工作台、业务资料、安装登记或其他插件。市场版重复安装不需要这个准备步骤。

该准备步骤保留旧工作区的页面和桥接版本。要使用本版新增的页面功能，请先用完整新版客户包更新应用文件，同时保留 `data/` 和附件；切换安装渠道本身不会自动覆盖旧应用文件。

首次启动会将随包资源（含压缩的官方 BioMCP）校验并展开到当前 profile 的 `medresearch-workbench/`，业务数据放在其中的 `data/`，不放进 `node_modules`。重新安装插件不会清空资料。已有有效的本地客户包安装登记时，继续使用原工作台目录，不自动迁移或覆盖旧资料。

受管目录升级若检测到桥接代码变化且旧服务仍在运行，会明确暂停并提示先停止旧服务再重试，避免两个版本同时写入同一资料库。

## 完整客户包快速开始

1. 阅读 `docs/客户安装与模型配置.md`。
2. 双击完整交付目录中的 **安装或升级医学工作台.cmd**；也可以在该目录运行：

   ```powershell
   node scripts\install-model-plugin.mjs
   ```

3. 重启 DeepSeek Harness。安装插件后，左下角“工作台”和“控制室”会自动出现“医学文献与证据工作台”项目；首次启动会创建项目、默认“窗口1”并绑定本目录的 `医学研究工作台.html`。不需要手动编辑布局或查找 HTML。
4. 点击该项目直接打开工作台。无 Zotero 也可用：首页/资料库点“＋ 导入 PDF”，选择自己的 PDF → 阅读、批注、笔记、问答、关联任务、保存。
5. 点击顶栏“模型”，选择：
   - **使用 DSH 模型**（默认，跟随当前绑定会话）；
   - **自定义 API**（OpenAI 兼容，填写 Base URL、模型、密钥）。
6. 本地文件服务会由插件自动检测/启动；失败时顶栏“本地服务未启动”可点“启动 / 重试服务”。Zotero 是可选来源，未安装/未启动只在选择“连接 Zotero（可选）”时提示，不影响 PDF 与保存。后台服务启动成功后可以关闭启动窗口。

首次使用默认空资料库，不自动加入演示资料、病例或任务。升级不会删除已有记录。旧版已出现的演示数据，可在页面顶部点“清除演示数据”并确认；只移除带 `demo:true` 标记的演示记录。需要演示时可在“数据与备份”主动载入。

已有资料缺少全文时，可在阅读台点击「为本资料选择 / 关联 PDF」补充自己的 PDF；原资料 ID、笔记和任务保留。Zotero 独立 PDF 附件按自身文件识别。Zotero 后来新增的附件需手动刷新或重新导入，工作台不在后台持续监听。

顶栏绿色“BioMCP 0.9.3”表示本地程序可运行；黄色“BioMCP 未就绪”可点击查看缺文件或启动失败原因。BioMCP 失败时会保留原因并使用备用来源；每次结果显示实际来源及部分结果提示。

本地服务必须属于当前项目目录。默认8765（或指定MEDWB_PORT）被旧目录/其他程序占用时，新版会自动选空闲端口并记住实际地址，不关闭占用者、不读取其数据。实际地址见“连接与来源”；宿主重开后仍核对项目归属再复用。

安装器将完整交付目录登记到当前 DSH profile 的 `.medresearch-workbench-installation.json`。即使宿主将插件复制进 node_modules，仍按登记找到 HTML 和文件服务。仅复制 plugin 文件夹不构成完整安装；请保留完整交付目录，换位置后从新位置重新运行安装入口。已有业务数据在 data/，更换交付目录时需完整保留该目录和上传文件。

已识别的旧实体插件副本会先完整保全到profile内的本次插件备份，再更新安装；失败恢复原副本和本插件配置。未知目录会停止处理并说明原因。安装器不迁移、删除或覆盖data业务文件。

新上传 PDF 使用项目相对路径并附带文件身份记录，移动目录时请保留整个 `data/uploads/`。无法证明来源的旧绝对路径会保留并提示重新定位，不按同名文件猜测替换。浏览器缓存按项目目录隔离；旧版未标明项目的缓存保留原样，不自动导入其他项目。

## 不包含什么

- 不含开发者账号、API Key、客户业务数据。
- 不含本机绝对路径依赖；宿主接口全部使用相对路径。
- 不含 Zotero 数据库直写/清库脚本；Zotero 仅只读导入。

## 主要文件

| 路径 | 说明 |
|---|---|
| `医学研究工作台.html` | 工作台单文件窗口（PDF.js 在 `vendor/pdfjs`） |
| `plugin/` | DSH 模型宿主插件（同源鉴权接口） |
| `scripts/install-model-plugin.mjs` | 宿主插件安装/回滚 |
| `bridge/server.mjs` | Zotero/PDF 本地桥接（端口 8765） |
| `fixtures/sample-paper.pdf` | 演示用开放获取 PDF（PLOS Medicine，CC BY） |
| `docs/客户安装与模型配置.md` | 安装、模型、错误状态与隐私说明 |

## 数据位置

工作台业务数据写入项目的 `data/workbench-data.json`（首次保存时创建）。模型密钥写入 DSH 宿主凭据库，不写入该数据文件、页面 localStorage、日志或备份导出。
